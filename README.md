# isotere.github.io

Личный учебный блог «Evangi · Гримуар капитала»: математика, финансы, Python и алгоритмические стратегии. Сайт собирается Zensical и публикуется на GitHub Pages через GitHub Actions.

Адрес после публикации: <https://isotere.github.io/>.

## Общие правила Codex

В рабочей области BLOG этот репозиторий размещается рядом с `codex_configs`. Канонические общие инструкции находятся в `codex_configs/AGENTS.md`; в BLOG на них указывает относительный симлинк `AGENTS.md`.

Отдельного `AGENTS.md` в этом репозитории нет. Общие правила читаются через `BLOG/AGENTS.md`, а специфика сайта хранится в `codex_configs/repositories/isotere.github.io.md`; общий файл указывает, когда её подключать. Для работы Codex открывай каталог BLOG либо явно подключай общий `../AGENTS.md` в сессии из отдельного репозитория. Сборка сайта остаётся самостоятельной и не зависит от каталога правил.

Git identity, `.githooks/`, `.github/` и `core.hooksPath` принадлежат этому репозиторию. Они не выносятся в общую папку и подключаются отдельно после clone.

## Локальный запуск

Нужны установленный Python и Make. По умолчанию используется Python 3.14, указанный также в `.python-version`. Окружение создаётся в `.venv` внутри репозитория. Активация окружения не требуется: Make вызывает его исполняемые файлы напрямую.

Из корня проекта выполни:

```bash
make install
make serve
```

`make install` создаёт `.venv` и скачивает зависимости из `requirements.txt`. Установка выполняется только по этой явной команде. Команды просмотра и сборки используют уже установленное окружение.

Сайт разработки откроется по адресу <http://127.0.0.1:8000/>. Он обновляется при изменении файлов. Для остановки нажми `Ctrl+C`.

Если интерпретатор вызывается другой командой или находится по отдельному пути:

```bash
make install PYTHON_BIN=/path/to/python3
```

Zensical требует Python 3.11 или новее. Для совпадения локального окружения и CI используй ветку 3.14. Все Python-зависимости этого проекта устанавливаются в `.venv`; настройки глобального окружения не меняются.

## Команды Make

| Команда | Действие |
| --- | --- |
| `make help` | Показать команды |
| `make venv` | Создать только `.venv` |
| `make install` | Создать окружение и установить зависимости |
| `make serve` | Запустить просмотр с черновиками |
| `make build` | Собрать публичный сайт в `site/` со строгими проверками |
| `make check` | Выполнить сборку и `pip check` |
| `make preview` | Собрать сайт и показать публичный результат на порту 8001 |
| `make clean` | Удалить результат сборки и кеш, сохранив `.venv` |

Другой адрес сервера разработки:

```bash
make serve DEV_ADDR=127.0.0.1:8080
```

У команд `make build`, `make serve` и `make check` нет автоматической установки зависимостей. При отсутствии окружения они подскажут выполнить `make install`.

## Навигация и главная страница

Верхнее меню содержит шесть разделов в заданном порядке:

1. «Блог» - общая лента всех четырёх тематических разделов, адрес `/`.
2. «Инвестиции» - обучение инвестированию и публикации этой темы.
3. «Финансы» - финансовая база и публикации этой темы.
4. «Математика» - математическая база и публикации этой темы.
5. «Разное» - записи, которые нельзя однозначно отнести к предыдущим трём разделам.
6. «О проекте» - страницы «Обо мне» (`/about/`) и «План обучения» (`/learning/`).

В `zensical.toml` включены `navigation.tabs` и `navigation.tabs.sticky`: на широком экране меню расположено под шапкой и остаётся видимым при прокрутке. На узком экране используется мобильная навигация. Вариант оформления - `modern`. В разделе «О проекте» доступны две отдельные страницы: «Обо мне» и «План обучения».

Верхняя плашка показывает эмблему ворона с гримуаром, название «Evangi · Гримуар капитала» и девиз «Магия начинается с матчасти.». Название и девиз остаются текстом и сохраняются при прокрутке длинной страницы. Заголовок текущей страницы остаётся в содержимом и названии вкладки браузера.

Название задаётся через `project.site_name`, девиз - через `project.extra.tagline`, эмблема - через `project.theme.logo` в `zensical.toml`. Шаблон `overrides/partials/header.html` сохраняет штатные поиск, ссылку на репозиторий, мобильное меню и верхние вкладки. Стили находятся в `docs/stylesheets/site.css`: высота верхнего ряда - от 96 px на широком экране и 88 px на узком, эмблема - 80/64/48/40 px в зависимости от ширины. При необходимости название переносится, не обрезаясь. Размеры текста статей сохраняются.

Верхние вкладки выбирают подборку: «Блог» показывает все статьи, а «Инвестиции», «Финансы», «Математика» и «Разное» - статьи своей темы. При открытии тематической подборки или полной статьи активна соответствующая вкладка. Для статьи с несколькими категориями используется первая категория.

Дублирующий список «Разделы» в левом меню не выводится. В «Блоге» остаётся месячный архив; справа сохранено оглавление записей текущей страницы. Мобильное меню содержит все верхние разделы и страницы «О проекте».

В тематических подборках левая колонка полностью скрыта штатным front matter `hide: [navigation]`, поэтому область статей занимает освободившуюся ширину. Правое оглавление и мобильное меню сохраняются. Это действует на всех страницах подборки; в «Блоге» колонка с архивом остаётся.

Активная тематическая вкладка определяется по категории статьи либо адресу ленты; это работает и для подборки без опубликованных записей.

Навигация настраивается штатными шаблонами из `overrides/`, подключёнными через `theme.custom_dir`. `blog_navigation.html` определяет активную тему по контексту страницы; `partials/tabs.html` и `partials/nav.html` используют стандартные компоненты Zensical для ссылок, сворачивания и мобильного меню. Это учитывает, что Zensical относит автоматически созданные категории к ветке «Блог». При обновлении закреплённой версии Zensical проверяй эти переопределения и переходы в браузере.

Лента использует `docs/index.md`: для этого `blog_dir` установлен в `.`. Статьи остаются в `docs/blog/posts/`, что явно задано через `post_dir`. Формат `post_url_format = "blog/{slug}"` сохраняет адреса статей `/blog/slug/`.

По прежнему адресу `/blog/` остаётся страница со ссылкой на главную ленту. Страницы «Обо мне» и «План обучения» входят в раздел «О проекте»; их адреса `/about/` и `/learning/` сохранены.

## Страница плана обучения

`docs/learning.md` содержит публичную версию спирального роадмепа. Вверху расположены семь карточек со ссылками на витки; далее идут темы, предпосылки, практика и критерии перехода, проекты P1–P6, параллельные линии и материалы. Все 57 дисциплин перечислены в раскрывающихся группах.

На широком экране карточки расположены в две колонки, на узком - в одну. Стили находятся в `docs/stylesheets/learning.css` и подключены через `extra_css`. Дополнительные JavaScript-библиотеки для карты не нужны.

Заголовки используют явные якоря через встроенный `attr_list`: `spiral-1`–`spiral-7`, `p1`–`p6` и якоря общих разделов. При редактировании сохраняй их либо обновляй все ссылки. Оглавление показывает уровни до третьего; четвёртый уровень остаётся в тексте для подробных подразделов. При изменении карты проверь переходы и читаемость на широком и мобильном экране.

## Лента, разделы и анонсы

Главная лента, архивы и тематические подборки создаются штатным механизмом блога Zensical. В ленте по пять записей на страницу; архив группируется по месяцам. В боковом оглавлении перечислены заголовки записей текущей страницы ленты. На странице полной статьи показывается оглавление её разделов.

Каждая тематическая лента содержит все опубликованные записи своей категории. `categories_pagination = true` и `categories_pagination_per_page = 5` делят её на страницы, сохраняя доступ к более ранним постам. Если записей не больше пяти, навигация между страницами не отображается.

Каждая статья существует в одном экземпляре внутри `docs/blog/posts/`. Категория назначается по папке через её `.meta.yml`: штатный механизм `meta` включён перед `blog`. Дополнительно можно указать другие разрешённые `categories` в статье; они объединятся с категорией папки. Общая лента включает записи всех четырёх разделов без дублирования. Допустимые категории проверяются при сборке:

| Папка | Категория в `.meta.yml` | Страница тематической ленты |
| --- | --- | --- |
| `investments/` | `Инвестиции` | `category/инвестиции.md` |
| `finance/` | `Финансы` | `category/финансы.md` |
| `mathematics/` | `Математика` | `category/математика.md` |
| `misc/` | `Разное` | `category/разное.md` |

Содержимое файлов в `docs/category/` выводится перед автоматически собранными анонсами соответствующей категории. Старые адреса `/investments/`, `/finance/` и `/mathematics/` перенаправляются на тематические ленты штатным механизмом redirects; дополнительный пакет для него не устанавливается.

В верхнем меню и ссылках на тематические подборки используются адреса готовых страниц `/category/<категория>/`. Для Zensical 0.0.73 это проверенный способ связать автоматически созданную подборку с меню сайта; ссылки на её `.md`-исходник не преобразуются в адрес публикации.

Граница анонса задаётся разделителем `<!-- more -->`:

```markdown
---
date: 2026-10-28
slug: example-investment-post
description: "Краткое описание статьи"
draft: true
---

# Заголовок статьи

Этот текст и нужные иллюстрации войдут в анонс ленты.

<!-- more -->

## Полная статья

Этот текст появится только после перехода к полной статье.
```

Пример предполагает файл в `docs/blog/posts/investments/`: категория «Инвестиции» унаследуется из `.meta.yml`.

Разделитель обязателен: `post_excerpt = "required"` останавливает сборку, если он пропущен. `description` используется как описание страницы и не заменяет видимый анонс. Значения YAML с двоеточием заключай в кавычки. Markdown, формулы, изображения и код можно использовать по обе стороны разделителя.

Демонстрационные Lorem-публикации удалены из всех четырёх разделов. Описания тематических лент сохраняются и доступны без опубликованных статей. Исходный авторский пример в `misc/` сохраняет `draft: true`; новые публикации будут появляться по мере готовности.

## Шрифты

Вариант темы остаётся `modern`. Шрифты подключены локально:

- заголовки - Balsamiq Sans Bold, вес 700;
- основной текст - Nunito Regular, вес 400, с прямым, курсивным и жирным начертаниями;
- цитаты - Victor Mono Italic;
- код - Victor Mono Regular;
- формулы - стандартные математические шрифты MathJax.

Основной текст - 16 px, межстрочный интервал - 1,65. Размеры H1–H6: 30/26/22/20/18/16 px; цитаты - 16 px, код - 13 px. Размеры заданы в CSS-пикселях и сохраняются при изменении ширины окна; масштаб браузера продолжает действовать. В карточках роадмепа заголовки - 16 px, подписи и описания - 14 px.

WOFF2-файлы, оригинальные лицензии OFL 1.1 и список источников с SHA-256 находятся в `docs/assets/fonts/`. Кириллица и латиница включены, наборы символов загружаются по необходимости. Объявления `@font-face` - в `docs/stylesheets/fonts.css`, назначение шрифтов и размеров - в `docs/stylesheets/site.css`. Загрузка шрифтов Google Fonts через тему отключена (`font = false`); браузер запрашивает эти файлы только у самого сайта.

## Иллюстрации

Эмблема `evangi-raven-emblem.webp` изображает ворона-учёного с гримуаром и компасом-шестерёнкой. Она создана встроенным imagegen в стиле остальных рисунков; фон прозрачный. Текст названия и девиза выводится шаблоном сайта отдельно от изображения.

Все рисунки выполнены в едином графичном стиле тёмного фэнтези: крупные цветовые плоскости, угловатые силуэты и рваные края. На главной остаются бык и медведь над общим учебником (`bull-bear-study.webp`), до 180 px по высоте.

В «Обо мне» четыре иллюстрации: разработчик за столом, картограф, мастер-аналитик и летописец с вороном. Персонажи условные и не служат портретами автора. На широком экране текст обтекает рисунки, расположенные справа, слева, справа, слева. Размер - до 315×210 px, максимум 45% ширины текста, зазор - 24 px; первая картинка примерно на 30% меньше прежней. Каждый заголовок подраздела начинает новый блок ниже предыдущего рисунка.

На узком экране обтекание отключается, текст занимает всю ширину, а картинки продолжают чередоваться по сторонам и занимают до 70% ширины. Изображения размещены локально в `docs/assets/images/`, используют WebP с прозрачностью. Подписи находятся в `figcaption`, набраны шрифтом сайта размером 14 px. Основной текст, заголовки и код сохраняют согласованные размеры.

Разметка находится в `docs/index.md` и `docs/about.md`, стили - в `docs/stylesheets/site.css` (классы `blog-illustration` и `about-illustration`). Полный список файлов, параметры экспорта и финальные промпты сохранены в [design/illustrations.md](design/illustrations.md); этот файл не входит в страницы сайта.

## Первая статья и новые публикации

Перед сдачей любого авторского текста обязательна редакторская проверка из общего `BLOG/AGENTS.md`, раздел «Редакторская проверка текстов блога». Она действует для страниц, статей, подписей и черновиков в Obsidian.

Начальный черновик находится в `docs/blog/posts/misc/2026-10-27-why-finance-through-code.md`. Он содержит вводный текст, формулу, пример Python и список того, что нужно заполнить перед публикацией.

Чтобы подготовить следующую статью:

1. Подготовь статью в личном Obsidian vault, в папке `Блог/Черновики`. По поручению на публикацию перенеси выбранный готовый текст в нужную папку `docs/blog/posts/`: `investments/`, `finance/`, `mathematics/` или `misc/`. Несколько черновиков можно вести параллельно; остальные остаются в vault.
2. Задай фактическую дату по Москве, постоянный `slug` и описание. Категория унаследуется из `.meta.yml` выбранной папки; для междисциплинарной записи можно добавить другие разрешённые `categories`.
3. Напиши анонс, добавь `<!-- more -->`, затем полный текст. Сохраняй `draft: true` до готовности.
4. Проверь вычисления и источники. Вычитай текст по ru-text и общим правилам BLOG: убери штампы, повторы, служебные реплики и выдуманные подробности, проверь выбранную пунктуацию ` - `. Прочитай статью целиком, затем выполни `make check`.
5. Удали `draft: true` или поставь `draft: false`. Перед коммитом посмотри публичную сборку через `make preview`.

Черновики видны при `make serve` и исключаются из обычной сборки. При этом их исходные файлы доступны в публичном репозитории. Приватные заметки и личные данные остаются вне репозитория.

Постоянные адреса статей имеют вид `/blog/slug/`. Не меняй опубликованный `slug` без перенаправления. Изображения добавляй в `docs/assets/images/` и связывай со статьёй относительным Markdown-путём, например `../../../assets/images/chart.png` для файла в `blog/posts/<раздел>/`.

Формулы записывай через `$...$` и `$$...$$`; они отображаются через MathJax. Библиотека загружается браузером с CDN. Шрифты текста и кода размещены локально; загрузка Google Fonts не используется. Мгновенная навигация пока выключена; при её добавлении проверь повторное отображение формул.

Из Obsidian переноси отобранный текст в обычном Markdown. Весь vault, Dataview и внутренние `[[ссылки]]` автоматически не публикуются.

## Приватность коммитов и GitHub Actions

В новых коммитах имя автора и коммитера должно совпадать с публичным логином из GitHub noreply-email. Для владельца этого блога используется логин `isotere`. Личная Git identity остаётся за пределами публичного репозитория; настройки сохраняются только в его локальном Git config.

После нового clone настрой защиту отдельно. Скопируй свой noreply-email из `Settings → Emails` на GitHub и передай его команде:

```bash
make git-privacy GIT_NOREPLY_EMAIL=YOUR_ID+isotere@users.noreply.github.com
```

`YOUR_ID` заменяется значением, которое показывает GitHub. При уже настроенном noreply-email достаточно `make git-privacy` без параметра. Команда задаёт локальные `user.*`, `author.*`, `committer.*`, `user.useConfigOnly` и `core.hooksPath=.githooks`. Глобальные настройки не меняются. Существующие сторонние hooks установщик сохраняет и при конфликте останавливается.

`pre-commit` проверяет effective identity, включая переопределения окружения. `pre-push` проверяет реальные метаданные всех отправляемых коммитов, включая промежуточные версии. При новом ref или неизвестной удалённой базе проверяется вся достижимая отправляемая история. Служебный committer GitHub допускается отдельно. Найденные личные значения в диагностике не печатаются.

Проверки без установки пакетов:

```bash
make privacy-check
make test-privacy
```

Первой команде нужна настроенная локальная identity. Вторая использует временные Git-репозитории с синтетическими данными и не меняет историю рабочего репозитория. Обе работают на стандартной библиотеке установленного Python.

Проверка identity не распознаёт произвольные персональные данные в содержимом. Перед commit отдельно просматривай staged-файлы, сообщения и trailers, изображения и документы. Перед push проверь отправляемую историю и подписи. В публичных материалах используй относительные пути и вымышленные данные. Личные Obsidian-заметки, брокерские реквизиты, токены и необработанные выгрузки остаются вне репозитория. Правила работы агента находятся в общем `BLOG/AGENTS.md`; специфика сайта - в `codex_configs/repositories/isotere.github.io.md`.

На GitHub также включи `Keep my email addresses private` и `Block command line pushes that expose my email`. Серверная блокировка проверяет email последнего коммита и не заменяет проверку всей отправляемой истории. Изменение настроек не удаляет сведения из старых коммитов. [Настройки приватности email](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/blocking-command-line-pushes-that-expose-your-personal-email-address).

Логи Actions публичного репозитория доступны другим пользователям. В workflow сохранены минимальные права токена; checkout не сохраняет credentials. До установки зависимостей проверяются метаданные коммитов и тесты защиты. Артефакт содержит только `site/`, исключает скрытые файлы, хранится один день и не загружается для PR. Срок хранения логов задаётся отдельно в настройках репозитория; `retention-days` артефакта не меняет его. [Защита workflow](https://docs.github.com/en/actions/reference/security/secure-use), [видимость логов](https://docs.github.com/en/enterprise-cloud%40latest/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility).

Не включай вывод полного окружения и Git config в CI. Маскирование секретов не гарантирует удаления произвольных PII из лога. Для сайта используются только штатный `GITHUB_TOKEN` и OIDC Pages; личные токены и приватные источники данных этому workflow не нужны.

## GitHub Pages и Actions

Для корневого сайта репозиторий должен называться `isotere.github.io` и принадлежать аккаунту `isotere`. Для публикации на GitHub Free выбери видимость `Public`.

В настройках репозитория открой `Settings → Pages → Build and deployment` и выбери источник `GitHub Actions`.

Workflow настроен на существующую ветку `master`:

- Push в `master` запускает сборку и публикацию.
- Pull request в `master` запускает проверку без публикации.
- `workflow_dispatch` позволяет запустить процесс вручную; публикация также разрешена только из `master`.

Если сменишь основную ветку на `main`, обнови фильтры событий и условие задания `deploy` в `.github/workflows/pages.yml`.

В CI выполняются те же `make install` и `make check`, что и локально. Python выбирается по `.python-version`; зависимости устанавливаются в отдельное `.venv` runner. Для публикации используется штатный `GITHUB_TOKEN`, а разрешения Pages получает только задание развёртывания.

После успешного workflow проверь сам сайт. Наличие зелёного статуса не заменяет просмотр ссылок, формул и иллюстраций.

## Свой домен

Свой домен можно подключить позже к тому же сайту. Основной порядок:

1. Подтверди владение доменом через TXT-запись в настройках Pages своего аккаунта GitHub.
2. Задай домен в `Settings → Pages → Custom domain` репозитория.
3. Настрой DNS: CNAME поддомена направь на `isotere.github.io`, для корня используй актуальные A-записи или ALIAS/ANAME по инструкции GitHub.
4. Дождись сертификата и включи `Enforce HTTPS`.
5. Измени `site_url` в `zensical.toml` на новый HTTPS-адрес, выполни сборку и проверь перенаправления и ссылки.

Для выбранного способа публикации через Actions файл `CNAME` в исходниках не требуется. DNS-запись CNAME настраивается у провайдера домена отдельно. Не создавай wildcard-запись `*` для GitHub Pages.
